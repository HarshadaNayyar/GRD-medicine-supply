# Local product audit — 1 November 2026

Scope: current GRD backend, React website, shared client contract, data ingestion, forecasting/planning, inventory execution, authentication, packaging and local operation. This report records executed checks and distinguishes them from deployment or business validation.

- PostgreSQL 16: **53 backend tests passed**, including competing approvals and all new audit regressions.
- SQLite: **52 passed, 1 skipped**; the skipped test is specifically PostgreSQL-only and passed in the PostgreSQL run.
- React: **18 web tests passed**. TypeScript and the production Vite build passed.
- Ruff and Git whitespace checks passed. The generated OpenAPI snapshot matches all **51 live API paths**.

## Issues fixed

| Area | Finding and resulting behaviour |
|---|---|
| Session isolation | Delayed responses could restore signed-out data, and an old 401 could clear a new login. Requests now carry a session generation; stale responses are discarded, refreshes are ordered, sign-out clears workspace state immediately, and upload expiry uses the same clearing logic. |
| Command retries | An unreadable successful JSON response could look like success. It now remains an explicit unresolved response, preserving the stock command's idempotency key for confirmation by retry. JSON calls/uploads have bounded waits. |
| Source comparison | A previous feasible source could remain selectable while quantity/destination changed or the next lookup failed. Only options matching the current inputs enable proposal creation. In-flight mutation dialogs cannot imply cancellation by being dismissed. |
| Freshness | PostgreSQL session-local timestamps were being relabelled as UTC, understating stock age by 5½ hours in this environment. Aware timestamps are now converted correctly; SQLite naive timestamps are treated as UTC. Audit timeline timestamps receive the same interpretation. |
| Stale batches | A fresh receipt could hide an older positive balance. Position age now uses the oldest positive batch timestamp; empty old batches do not block supply, and live dispatch rechecks allocated stock freshness. |
| Counts | New count cases capture the batch timestamp as well as quantity, blocking an adjustment after stock moves and returns to the same numerical balance. Older cases lacking that timestamp retain the existing quantity check; recount those before any real pilot. |
| Cases | Adding a comment could erase a deadline, while assignment could not be cleared explicitly. PATCH now preserves omitted fields and accepts an explicit null to clear owner/deadline. |
| Background jobs | Late results could overwrite a recovered/cancelled calculation. Completion/failure now locks the row and checks the exact running lease. Cancellation also locks before checking state. |
| Data imports | Provenance types were insufficiently validated; duplicate CSV headers could silently replace values. Metadata is typed and bounded; duplicate headers, empty files and malformed workbooks fail cleanly. File extensions are case-insensitive. Preview controls are frozen while a file is being checked/committed. |
| Data access | The source register could stop at the first 200 datasets. API/client now page through it. Destination operators receive the shipped batch label/expiry without receiving access to source inventory. |
| Forecast evidence | Published sales forecasts no longer replace available requested-demand projections. Failed/new series loads clear old chart history, imported-source changes refresh it, short-history fallback text is explicit, and assistant answers clear when their question/reference changes. |
| Simulation | Zero demand no longer invents a minimum demand rate. Simulated outcomes retain their synthetic label even when the input organisation has observed records; source evidence is labelled separately. |
| Planning/UI | All planning views enforce the scenario date even when there are no candidates. Missing stock/history creates a data-check action instead of an all-clear queue; incomplete expiry projections are not displayed as a measured zero. Approval/cancellation controls respect both endpoint scopes. Fractional receipts/counts are blocked in the interface. |
| Authentication inputs | Password whitespace is preserved rather than silently stripped; invalid random seeds are rejected; the sample token-secret placeholder cannot be used as a deployment secret. |
| Readability | Text contrast was reviewed across sign-in and the six workspaces, with improvements to status badges, inactive tabs, table actions, source limitations, timeline labels, map controls and charts. Desktop/phone layout checks supplement the component tests; this is not a complete assistive-technology certification. |
| Performance | Added a demand-series composite index and replaced per-batch reconciliation lookups with one aggregate query. CI now runs the whole suite against PostgreSQL and the OpenAPI snapshot was refreshed. |

## Larger-data read-load check

Reproducible command: `.venv/bin/python scripts/audit_performance.py`. It creates and removes its own database; it never reads or modifies the team's database. Workload: **100 products × 5 sites × 730 days = 365,000 demand observations**, with **10 parallel authenticated read requests** per endpoint using the same synthetic test account.

| Endpoint | Median before index | Median with index | P95 before index | P95 with index |
|---|---:|---:|---:|---:|
| Network projection | 1,633.7 ms | 93.7 ms | 3,032.5 ms | 281.5 ms |
| Demand page | 375.1 ms | 151.6 ms | 843.9 ms | 497.1 ms |

This bounded in-process SQLite run isolates the series index while other audit fixes are present in both phases. It measures API responses, not rendered-page time. Ten samples, shared-account requests and local hardware are not a substitute for ten complete interactive user sessions, hosted capacity testing or production certification. Reconciliation separately has a regression test verifying one aggregate SELECT rather than two extra queries per batch.

- Android/iOS applications, persistent offline queues, camera scanning and push delivery are separate work; a responsive website is the current client.
- Approved GRD transaction data and operating policies are still needed. The demo uses declared synthetic data; weather context is separate and no local forecast gain or measured GRD benefit is claimed.
- Full network optimisation/replay, real carrier reliability and pilot outcome evaluation remain outside the implemented single-lane evidence boundary.
- The test toolchain emits a non-failing Starlette/httpx deprecation warning. CI configuration is supplied and locally exercised in equivalent steps; remote GitHub CI has not been run by this task.

These are the checks executed for this release, not a promise that every possible input, device, browser or production failure has been exhausted.
